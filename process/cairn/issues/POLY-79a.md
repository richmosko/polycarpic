Two docs-tooling defects found 2026-10-31 while landing PR #67: the docs server cannot restart right after it is stopped, and Mermaid drops `<br/>` line breaks in node labels.

## Context

1. **Restart fails with `OSError: [Errno 48] Address already in use`.** After the 8765 server is killed, sockets linger in TIME_WAIT and `scripts/serve-docs.py`'s `socketserver.TCPServer` refuses to bind until they clear (~30s on macOS). Took three attempts to restart after the PR #67 merge.
2. **Mermaid label line breaks are dropped.** ARCH §1 System Context labels are authored with explicit breaks (`app["Web app<br/>+ API"]`, `backup[("Off-box<br/>backup")]`, `idp["Login IdPs,<br/>Resend"]`) but render run together on one line ("Web app+ API", "Off-boxbackup"). Present on `main` before and after PR #67, so it's in the shared loader (`docs/_assets/mermaid-init.js`, generated by `scripts/vendor-mermaid.sh`), likely the `htmlLabels` / label config, not the diagram source. Check every doc's diagrams, not only ARCH.

## Acceptance criteria

- [ ] `serve-docs.py` restarts on the same port immediately after the previous instance is killed (e.g. `allow_reuse_address = True`), with a test that binds, closes, and rebinds.
- [ ] Mermaid node and edge labels honour `<br/>` in all four docs, light and dark, and in the PDF export; edge-label contrast and the doc-theme logic from PR #67 stay intact.
- [ ] Fix lands in the generator (`scripts/vendor-mermaid.sh`) as well as `mermaid-init.js`, so a re-vendor doesn't regress it.
- [ ] PDFs regenerated for every doc with a Mermaid diagram.
