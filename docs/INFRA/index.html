1. Targets & Topology

Ruled order (Principal, 2026-11-06): a Hetzner VPS, then a local-network box, then Vercel + Neon. ARCH §7 says what each is; SECURITY C-70 to C-77 say why it is built this way; this document says how to stand it up and run it. The three are deployment targets of one application, not three architectures.

1.1 Reading this document as the operator

  • You are one person running one instance for your own household (PRD §3). Nothing here is written for hosting other people, and nothing here makes that safe (SECURITY R-6).
  • If you only read two sections, read §7 (to stand it up) and §8 (to keep it alive). Everything else is the reasoning behind them.
  • Terms: the box is the machine running the containers; the operator is you; a digest is the exact fingerprint of one build of the app image (sha256:…); compose is the tool that starts the containers listed in compose.yml.

MachineOne Hetzner Cloud server, 4 vCPU / 8 GB / shared x86, Ubuntu Server 24.04 LTS (§2.1). IPv4 and IPv6 both enabled on the server; both are covered by the firewall rules.
PortsThe Cloud Firewall (outside the host, C-71) admits 22, 80 and 443 only. On the host only Caddy publishes ports; the compose-policy lint (C-70) and the post-deploy outside-in scan (§7.1 step 14) both enforce this.
SSHKey-only, no root login, no password auth. Port 22 stays open to the world because a home connection's address changes. The key and the unattended-upgrade posture are the control (§3.1). Restricting 22 to your current address in the firewall is an option, not the default, and a mistake there locks you out (§8.9).
DNSTwo A/AAAA records: app.<domain> to prod, staging.<domain> to staging, both pointing at the one server. Public DNS is at the zone's DNS host (§10 Q1 recommends Cloudflare DNS-only, no proxy).
TLSCaddy obtains and renews public certificates by ACME HTTP-01 (port 80). No operator action. Staging sits behind Caddy basic auth plus an IP allowlist (ARCH §7.1).
Third parties on this pathGitHub (image registry, release metadata, attestations; pulled by the box, §4.4); Resend (outbound mail); Plaid, SimpleFIN, direct broker APIs, the EOD price provider (OQ-5) and BLS (outbound, worker); Google, Apple and GitHub OAuth; the backup bucket; one outside monitor. Each is outbound-only from the box except the browser's own redirect.

ConcernDecision
Who may reach itBrowsers on the LAN only (C-76). No inbound path from the internet exists: the router forwards nothing, UPnP and NAT-PMP are off, the host drops inbound IPv6, and nftables allows 443 (80 redirects) and SSH from the LAN CIDR only. Away from home there is no access in v1.
Outbound allowlistDNS, NTP and TCP 443 only (C-76). Consequence found here: an SFTP upload to a Hetzner Storage Box uses port 22 or 23 and is blocked, which is one reason §9 rules the backup destination to an S3-compatible bucket over 443 on every target.
DNSReal-domain mode (default): the name is polycarpic.home.<domain>, defined only on the LAN (router DNS override, or one hosts-file line per device). There is no public A or AAAA record for it. The public zone holds only short-lived _acme-challenge TXT records written by Caddy. .local mode: the name is polycarpic.local, answered by mDNS or the same LAN DNS override.
TLSTwo modes selected by TLS_MODE (§3.4): real-domain (DNS-01 wildcard from a public ACME issuer) or private-ca (name-constrained operator CA). The app refuses to start on a mismatch (ARCH §7.8, SECURITY C-76).
Third partiesSame as §1.2 minus nothing; all are outbound over 443. OAuth sign-in works in real-domain mode and is disabled server-side in private-CA mode. A verification email link only opens from the LAN.
HardwareAny x86-64 mini PC or small server with a TPM 2.0, UEFI Secure Boot, 8 GB RAM or more, a 256 GB or larger SSD, and wired Ethernet. Put it on a small UPS. Buying advice is in §7.2 step 1.

ConcernDecision
ShapeTwo Vercel projects from one repo, one Neon project (ARCH §7.6, SECURITY C-61). No Caddy, no worker container, no deploy timer: Vercel deploys on a Git push to the production branch/tag, and migrations run as a build step.
ConnectionsRuntime uses Neon's pooled endpoint (PgBouncer, transaction mode). The migrate build step uses the direct endpoint, because a migration that sets role or takes advisory locks must not run through a transaction-mode pooler (§9.1 ruling D-6).
FreshnessHobby cron is once a day. Imports and period-end jobs run daily at best (ARCH §7.6, accepted).
BackupsOQ-26 answered in §6.6: Neon's restore window plus an operator-run weekly encrypted export; a nightly automated export is recommended before real data and needs a SecEng ruling.
When to use itWhen you have no machine you trust to keep running, or as a temporary landing place while a primary is rebuilt. It is the weakest target for secrets (SECURITY R-3). Do not link real aggregators here until POLY-77 and the R-3 review.

Planned total caps are about 7.1 GB for a prod+staging host that is never fully busy at once; the host keeps the remainder. Unmeasured. If docker stats after POLY-M1 shows the caps are hit, raise the plan size before raising a cap.

  • Only caddy has a ports: mapping. On the local box it is bound to the LAN address ("192.168.1.20:443:443"), never 0.0.0.0.
  • Every container: non-root user, read_only: true with named tmpfs for writable paths, cap_drop: [ALL], security_opt: [no-new-privileges:true], restart: unless-stopped, a healthcheck. No Docker socket is mounted anywhere.
  • The compose-policy lint (C-70) is a CI job that parses the rendered config (docker compose config) and fails on any violation of the list above, any secret in environment:, any ports: outside caddy, or any service on both project networks.
  • Postgres runs with the C-75 settings from a mounted postgresql.conf fragment: log_parameter_max_length = 0, log_parameter_max_length_on_error = 0, log_statement = 'ddl', plus archive_mode = on, archive_timeout = 300 and archive_command pointing at the spool script (§6.2).

3.2 Secret files on the host

Every operator secret is a file under /etc/polycarpic/secrets/ (staging: staging-secrets/, different values, no shared file). Compose mounts each file as a secrets: entry at /run/secrets/<name> into only the containers listed in §2.2. The app reads them through the *_FILE convention and refuses to start if one is missing or if a secret-looking environment variable is set in production (SECURITY §6.2).

The Hetzner data volume's LUKS key is a file on the root disk (/etc/polycarpic/luks.key, 0400). That protects against a detached or snapshotted volume only; it does not protect against someone who gets the running server or its root disk. Said plainly so nobody believes more than that. The home box does better (TPM, §3.5).

3.3 SSH, GitHub token, signing

  • Operator SSH. One ed25519 key per laptop, listed in ~/.ssh/authorized_keys of a non-root sudo user polyops. Root login and password auth are off. Adding or removing a laptop is §8.8. Hetzner's console is the break-glass path if you lose every key.
  • The box's GitHub credential (ARCH §8.1). A fine-grained personal access token, this repository only, contents:read and packages:read, expiry 90 days, stored as github_read_token and used only by the deploy script. If the package and repository become public, delete it. Renewal is §8.4. A reminder is set 14 days before expiry by the same outside monitor (§6.5).
  • Release signing. The prod tag is accepted only if its SSH signature verifies against /etc/polycarpic/allowed_signers. That file is installed at bootstrap from your own machine, not fetched from the repository: a copy pulled from the repo would be forgeable by whoever can push to it (ruling D-5, re-fold R-3).
  • Image trust. gh attestation verify pins the repository and the signer workflow .github/workflows/build.yml (§4.4).

Gate item (SECURITY R-20): before the first home-box deploy in private-CA mode, run the name-constraint test of §7.3 step 6 on each browser and OS you use. If any browser ignores the constraint, that browser must not have the root installed, and the box moves to real-domain mode.

3.5 Home-box disk unlock (TPM)

LUKS2 with two key slots: a TPM2 slot sealed to Secure Boot state (PCR 7), and a long recovery passphrase kept offline. Use PCR 7 only by default. Adding PCR 11 (the kernel image) makes every kernel update change the measurement and leave the box locked after the automatic reboot, unless the distribution ships signed PCR policies; whether Ubuntu 24.04 does is unmeasured and is a first-deploy measurement (SECURITY C-72 already marks PCR 11 per-distro). Firmware checklist, console hardening and verification are in §7.3 step 4.

3.6 The recovery sheet

One printed page, kept somewhere that survives a house fire, listing: where the password manager's emergency kit is; the age private key (as the AGE-SECRET-KEY-… line); the credential keyring offline copy; the LUKS recovery passphrase; the private CA root key (private-CA mode). The age key and the keyring are written on separate lines of separate sheets and never in the same file; a lost keyring costs a relink (RB-4), a lost age key costs every backup (§6.1). Nothing on the sheet is stored on the box or in a backup.
